# 设计草稿（只给评审看，不影响产品代码）

这两个文件是**草稿**：它们不参与构建、不被插件加载，纯粹用浏览器打开看效果。
产品的真实代码在 `client/index.jsx`（设置页）与 `tools/portal_console.py`（控制台页面），
本目录**不修改**任何产品代码。

| 文件 | 是什么 | 怎么看 |
| :--- | :--- | :--- |
| `settings-draft.html` | 插件设置页的**全页重排**草稿 | 浏览器直接打开；右下角可切「宽版 / 窄版(现状 560px)」与深浅色 |
| `console-draft.html` | 手机控制台页面的**重做**草稿 | 浏览器直接打开；右下角切深浅色。按手机宽度看最准 |

## 为什么先出草稿
你要求"先给我看一个修改的草稿页面，而不是直接修改"。理由是这类改动一旦落到
真代码里，改回去的成本很高（涉及 76+ 项控制检验与端到端测试）；先用静态 HTML
把**结构与信息层级**定下来，确认后再落地成真组件，返工最少。

## 草稿里一并暴露的 3 个真 bug（控制台）
这三个是我在只读排查时**实测**出来的，不是推测；它们会在落地时一起修：

1. **「编辑」是死链**：`_service_card()` 生成 `GET /_api/services/<key>/edit`，
   而 `portal_run.py` 里**没有这条 GET 路由** —— 实测三个服务全部返回 404。
   点「编辑」就是打开一个错误页。
2. **上游死了仍显示绿色「已启用」**：`_service_card()` 的判定顺序是
   `if enabled: on` **先于** `elif alive is False:`，所以只要开着就永远是绿点。
   实测 `realapp`（上游 2460 无进程）显示绿点「已启用」。
3. **点「添加服务」后跳出一屏 JSON**：表单 `POST /_api/services`，服务端
   `_send_json(200, ...)` 且**无重定向**。手机上提交后停在原始 JSON 上，
   得手动后退 —— "功能对、体验差"的典型。
